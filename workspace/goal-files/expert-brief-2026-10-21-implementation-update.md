## 2. Discovery execution repair — complete (one acceptance item pending)

**Root cause, sharper than the brief's framing:** all 10 discovery slot jobs were `space_action` crons — the job body containing any verification logic **never executed**; the scheduler invoked `runmarketdiscovery` directly and marked success from the transport result alone. Success was asserted by the transport layer, verified by nobody. Also established: **resume semantics do not exist** — every re-invocation creates a new run id/lease and restarts; checkpoints are observability/death-proofing only, so resume-looping was never available as a fix. Ceiling math: healthy run ≈102s vs the 120s worker ceiling; a stale-tier run added 92–96s of in-run tier refresh → guaranteed sever mid-flight.

**Fix shipped:** (a) all 10 slot jobs converted in place (ids/schedules/owner preserved) to verify-or-fail agent jobs: baseline → invoke → read-back; success only with an attributable terminal run row; bounded retry that first re-checks for the slot's own row (a late landing is adopted, never duplicated); failure reported loudly otherwise. Read-back states are the honest three: VERIFIED-EXECUTED / VERIFIED-NOT-EXECUTED (only with an independent "did not start" record) / UNVERIFIED — a missing read-back is recorded as **execution unknown**, never as proof of no execution. (b) Tier refresh separated: a standalone job (2h cadence, ~25 min ahead of slots) keeps tiers warm; live fire measured **~17s** (vs 92–96s in-run). (c) No public finalize action exists for stranded rows — detect-and-report only, stated as a limit.

**Live verification:** Tier job's first scheduled fire PASS (snapshot 42→43 verified by read-back). Live slot #1 (0300 ET, Oct 21) PASS: **discovery run 136**, verified-executed, terminal/degraded, 3 signals; **handoff 53** formed at its completion instant. Runtime before → after tier separation: 101–113s (margin ~18s; stale-tier runs severed at 120s) → **81.7s (run 135, manual pilot) / 89.0s (run 136)**, tier stage 59ms, margin ~31–38s. Remaining acceptance item: slot #2 (~0700 ET) under the hardened bodies, same verification. The P3 recovery watch ran untouched throughout and fired nothing.

**Probe scope, stated exactly:** the controlled probe proved the verify-or-fail *reporting* path for a definitely-nonexistent action — an unverifiable invocation is reported as failure-to-verify rather than success. It does **not** prove the platform invocation can never silently drop.

**Self-correction, on the record:** an interim build report claimed live slot #1 was "blocked by a scheduler-wide dispatch stall." That was wrong — it rested on a background timer's printed clock disagreeing with the epoch timestamps in the same tool outputs; grounded on the epochs, neither job was due yet. No stall occurred. The claim is withdrawn in the workstream record with the lesson logged.
